# USD for new tuition operations

Base: main `18b64e9d7dbbdf363fc49bc0610d30fe67489f35`. This change is independent of the import-recovery PR awaiting a separate CSV product choice. It addresses the remaining new-write part of PROGRAM-CURRENCY-01, with obsolete pricing-path retirement BB2-04 where caller verification proves it safe. ## Verified boundary

The settled rule is USD-only new tuition and external-payment writes, preserving confirmed historical records and exact retry/recovery. PR172 covers external payments and PR175 covers new local plan definitions. Three supported provider workflows can still create non-USD obligations from older plans or requests: plan price synchronization, enrollment activation and invoice creation.

A blanket currency validator on a request schema or workflow entry would reject historical replay before it reaches saved evidence. An existing operation record is also insufficient to justify a fresh price: a registered but never-attempted price remains a new financial write, even when its product step succeeded. Preserve original hashes, canonical caller keys, provider keys, account generation, attempts and confirmed outcomes. A response lost after provider success remains an unknown outcome requiring the existing recovery path.

## Bounded implementation

- Validate the actual currency for fresh financial work. Missing or blank stored plan currency cannot authorize a new price by falling back to USD. Keep historical request hashing and provider replay payloads unchanged. Keep normal new-invoice schema defaults, which are an explicit application default, separate from unknown provider facts.
- Price sync: preserve completed/projected/provider-success handling and product-only maintenance that reuses an exact historical price. Before executing any product step for a new price, require USD if the price has never been attempted. Inspect saved steps for an already registered plan. Recheck at the price write boundary after confirmed/blocked-state handling and before marking a request in flight. Use existing legal rejection transitions for wholly unattempted work; retain partial product evidence and reconciliation for interrupted work. Do not expand the current public recovery coordinator or rewrite its SQL state machine.
- Activation: reject a fresh non-USD activation before price-generation adoption, subscription reservation or intent persistence. Recheck never-attempted provider work under its existing owner. Preserve completed results, verified provider-success projection and already-attempted recovery. An existing metadata dictionary alone must not authorize a new non-USD provider attempt. Keep consent, quantity locks, exact price identity, account generation and old-provider-link refusal.
- Invoice creation: check new local intake after same-key lookup and before insertion, retaining exact request-hash collision handling. Refuse an existing but never-attempted non-USD invoice-creation intent before its first provider write. Preserve an already attempted or confirmed invoice operation and its owned continuation. Existing invoice collection, void/refund and reconciliation remain available; this change does not reinterpret their amounts or currencies.
- Retire the unused `_sync_plan_price` implementation and `_find_plan_price` lookup if final repository-wide caller inspection still finds only their private forwarding wrappers. The supported route calls the durable `BillingPlanSyncWorkflow`. These wrappers are not a documented extension interface; retaining a second unowned price writer would preserve the same accidental complexity and a currency bypass. Keep the recurring-interval helper used by the durable owner.

No new currency framework, provider infrastructure, schema migration or historical backfill is planned. If current state transitions cannot represent a safe rejection, revisit the boundary before coding around them. One coordinator owns integration.
